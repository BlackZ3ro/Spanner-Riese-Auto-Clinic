# U3-21: Customer repair-status lookup, proposed plan (for Gary to approve)

> **Superseded 28 Sept 2026.** Gary built the lookup on mobile using a dedicated random `reference_code` column and the `get_booking_by_reference_code` function (recorded in `supabase/migrations/0006`). Kept for the history of the decision.

Confirmed at the 22 Sept consultation: a customer enters a reference code and
sees what stage their car is at, **with no login**. This plan is a proposal
and has not been built or applied.

## The problem with using `invoice_number` alone

`bookings.invoice_number` already exists and is generated by the database as a
sequence (for example `INV-00005`). It is printed on every invoice and shown
in both apps, so customers already have it. But it is **guessable**: anyone
could type `INV-00001`, `INV-00002` and so on and see other people's cars.

## Proposal

**The customer enters two things: invoice number and vehicle registration.**
Both are already on their paperwork, so no new column or code is needed, and
someone who guesses an invoice number still needs the matching registration.

**The database answers through one function.** There is no public read access
to `bookings`. The function returns only the few fields the customer needs.

```sql
-- Draft for 0006_repair_status_lookup.sql - NOT applied. Gary to review.
create or replace function public.get_repair_status(p_invoice text, p_registration text)
returns table (vehicle text, stage text, booked_at timestamptz, closed_at timestamptz)
language sql
security definer
set search_path = public
as $$
  select b.brand || ' ' || b.model,
         case when b.status = 'closed' then 'Ready for collection'
              when exists (select 1 from jobs j where j.booking_id = b.id and j.status <> 'completed')
                then 'Being worked on'
              else 'Checked in' end,
         b.created_at,
         b.closed_at
  from bookings b
  where upper(b.invoice_number) = upper(trim(p_invoice))
    and upper(replace(b.registration, ' ', '')) = upper(replace(p_registration, ' ', ''))
  limit 1;
$$;

revoke all on function public.get_repair_status(text, text) from public;
grant execute on function public.get_repair_status(text, text) to anon, authenticated;
```

**Where the page lives:** a new page on the ASP.NET web app, `/Status`,
outside the login gate (the first unauthenticated route, see
`system-architecture.md` point 5). It is a two-field form that shows the
result or "No booking found", and it gives no hint about which field was
wrong.

## Things Gary needs to confirm

1. The real `jobs.status` values. The draft uses `'completed'` (what `Jobs/Details` writes; default is `'pending'`); mobile writes `booking_labor`, which has no status.
2. That `registration` is always filled in on bookings (mobile requires it).
3. Whether "stage" needs more steps than Checked in, Being worked on, and Ready for collection. Adding more would need a new status column.
4. Who owns the build: there is still **no owner**. Suggestion: Gary applies the SQL, and Ofentse or Breyton builds the `/Status` page as their code contribution.
