Step 2: Prepare the ASP.NET Project

Open your group's existing ASP.NET project, or create it if the project has not yet been prepared.

Use the ASP.NET approach selected for your approved design, such as ASP.NET Core MVC.

If using MVC, organise the project appropriately:

Project component

Purpose

Models

Represent the information used by the application

Views

Display the web pages

Controllers

Handle requests and coordinate application functions

Services

Organise communication with Supabase and other required services

Keep the web application in the web/ folder of your existing GitHub repository.

Check that the application launches successfully before implementing the remaining functions.

For additional guidance on project setup and MVC structure, use the Get started with ASP.NET Core MVC | Microsoft Learn .

Step 4: Implement Navigation and Forms

Connect the web pages so users can move through the application.

Implement the required forms and input validation.

Short example: A staff member opens the appointment list, selects a request, reviews its details and approves or rejects it.

The application must provide clear feedback when an operation succeeds or fails.

Use your SRS to determine which functions should be accessible to each user role.

Step 5: Connect ASP.NET to the Shared Supabase Backend

Connect the ASP.NET application to the same Supabase project configured in Activity 4.1 and used by Flutter in Activity 4.2.

Implement the database operations needed by the web application.

Operation

Salon example

Create

Add a record where the staff role permits it

Read

Retrieve appointment requests

Update

Approve or reject an appointment

Delete

Remove a record only where permitted by the SRS

Use an appropriate Supabase integration approach for your ASP.NET project. Keep sensitive credentials in secure server-side configuration, not in browser code or the GitHub repository.

Where users sign in, ensure the backend applies the required permissions to their requests. Do not use unrestricted administrative access as a substitute for implementing the approved user roles.

Step 6: Implement the Main Web Functions

Develop the functions identified in Step 1.

For each function, confirm that the relevant user can complete the intended process.

Short example: Approving an appointment

  1. Staff sign in to the ASP.NET web application.
  2. The application retrieves the appointment requests from Supabase.
  3. Staff select a request and choose Approve.
  4. The application updates the appointment status in Supabase.
  5. The updated status is displayed in the web application.

In Activity 4.4, the group will demonstrate that the same status can be retrieved through the Flutter application.
