Step 4: Demonstrate a Complete Shared Process

Select at least two important processes from your approved requirements that involve both applications. Where possible, demonstrate information flowing in both directions.

For each process, check what happens from the first user action to the final result.

Short example: Salon appointment system

  1. A customer submits an appointment request in Flutter.
  2. Flutter saves the request in Supabase.
  3. A staff member opens the ASP.NET web application.
  4. The web application retrieves the same request from Supabase.
  5. The staff member approves the request.
  6. ASP.NET updates the appointment status in Supabase.
  7. The customer refreshes or reopens the relevant Flutter screen and sees the updated status.

The final step does not need to happen automatically unless real-time updates form part of your approved requirements. Supabase supports real-time change subscriptions, but these must be configured and implemented if needed.
